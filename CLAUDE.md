# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Cheyn Verde (package name `zg`, formerly "Zona Green"): Angular 22 + Supabase platform — public educational content about cannabis/intercultural health, a private marketplace ("Selección informada") with WhatsApp checkout, and an admin panel. UI copy and code comments are in Spanish.

## Commands

- `npm start` / `npx ng serve --port <port>` — dev server (default 4200).
- `npm run build` — production build to `dist/zg/browser`. Use it to confirm CSS survives minification when touching `src/styles.css`.
- No unit tests (no `*.spec.ts` under `src/`, no `test` target). Functional tests are Playwright in `e2e/`: `npm run e2e` (purchase end to end + permissions matrix against the LOCAL Supabase; needs `npx supabase start` and, on an empty DB, `bash supabase/pruebas/preparar-base-local.sh`) and `npm run e2e:produccion` (read-only smoke test of the live site). Single test: `npx playwright test -c e2e/playwright.local.config.ts compra -g "stock"`. `.github/workflows/pruebas.yml` runs the local suite on every PR and the production smoke test daily.
- Prettier is configured (`.prettierrc`); there is no lint setup.
- Supabase CLI is not a dependency; run it with `npx supabase …`. The repo is linked to project ref `rvxxszdtocnhmdsrfkoi` (`supabase/config.toml`, local settings only — never `supabase config push`; `[db.migrations] enabled = false` on purpose, the local DB is built by `supabase/pruebas/preparar-base-local.sh`). Edge Functions live in `supabase/functions/`. Older schema dumps/migrations are in `docs/supabse/`.
- The production database is shared by dev and prod. Schema changes go as files in `supabase/migrations/` (each with a commented rollback) and the developer applies them by hand; restrictive ones wait in `supabase/migrations_pendientes/` until the frontend that no longer needs the old access is deployed. Production has no migration history table, so don't use `supabase db push`.
- `supabase/pruebas/` also has standalone API/Playwright scripts from the audit phases that only run against a local Supabase (`npx supabase start`, Docker) and refuse any other host. `node supabase/pruebas/generar-environment-local.mjs` + `npx ng serve --configuration local --port 4202` points the app at it; see `supabase/pruebas/LEEME.md`. The Supabase "Confirm signup" email template is versioned in `supabase/templates/` and must be pasted into the dashboard by hand.

## Architecture

- **Entry point is `src/setup/`** (`app.ts`, `app.config.ts`, `app.routes.ts`, `theme.config.ts`), not `src/app/`. Path alias `@src/*` → `src/*`.
- **Zoneless** change detection (`provideZonelessChangeDetection`), standalone components, signals; `@ngrx/signals` stores in `src/app/core/state/` (`UserStore`, `CartStore`, `AppConfigStore`, `DarkModeState`).
- **Routing**: every route except `/lab` is a child of `MainLayout` (navbar + footer). Feature routers (`features/customer/auth/auth.router.ts`, `features/marketplace/marketplace.router.ts`, `features/admin/admin.route.ts`) are spread into it.
- **Auth/guards gotcha**: guards read `UserStore` (hydrated synchronously from `localStorage['user-profile']`), not the Supabase session directly. `SupabaseAuthService.currentUserEvent` is a `BehaviorSubject` seeded with a fake `{INITIAL_SESSION, session: null}`; `app.ts` skips that seed, reloads profile/cart/roles on real auth events and clears a leftover profile when the real `INITIAL_SESSION` has no session. The `roles` table is readable only by authenticated users, so `app_roles` can be empty before login; `roleGuard`/`homeGuard` go through `core/guards/zonas-permitidas.ts`, which refetches roles when needed (a missing role used to loop `/home` ↔ `/seleccion` and freeze the tab). Login authenticates against Supabase Auth first; `SupabaseDbService.existeCorreo()` (RPC `existe_correo`) only decides whether to offer registration.
- **Phones (one per person)**: `perfiles.telefono_normalizado` is a generated column from `public.normalizar_telefono()` (international format, `+57…` for Colombian mobiles, foreign numbers must include `+`/`00`), and `shared/utils/telefono.ts` (`normalizarCelular`) mirrors that rule in the browser — change both together. Registration and Mi perfil call the RPC `estado_telefono` (via `SupabaseDbService.estadoCelular`) before saving; a unique index enforces it in the DB. Birth dates are calendar dates: use `shared/utils/fechas.ts` (`fechaDesdeISO`/`fechaAISO`), never `new Date('YYYY-MM-DD')` or `toISOString()`, which shift the day by time zone.
- **Referrals**: `perfiles.referido_por` keeps the code text the person typed, but the source of truth is the `referidos` table (one row per referred profile → `referente_id`, `estado` resuelto | no_resuelto | asignado_manual), filled by the `tr_registrar_referido` trigger on `perfiles` insert; `codigos_invitacion_historial` records every code a profile had. Both tables are admin-read-only via RLS and written only by SECURITY DEFINER functions (`arbol_referidos`, `ranking_referentes`, `admin_asignar_referente` require admin; `mis_referidos_conteo` returns only a number). Admin UI: `/admin/customer/referidos`. Supabase grants EXECUTE to `anon` on every new function, so migrations must `revoke … from public, anon, authenticated` explicitly.
- **Phase 3 hardening**: cart quantities must be positive integers (DB check); `procesar_checkout` requires an active profile and locks products in `producto_id` order; `productos.reservado` is no longer used (availability = `stock_total` minus what the user already has in the cart); users cannot change `correo`, `created_at`, `deleted_at` or `datos_adicionales` on their own profile (`proteger_campos_perfil`); minimum age 18 (`fechas.ts` + pending trigger); passwords need 8+ chars with letters and digits. `src/index.html` pins `@tailwindcss/browser` to an exact version with an SRI hash — to upgrade, change the version and recompute the sha384 of `dist/index.global.js`. `vercel.json` sets security headers and a CSP in **Report-Only** mode.
- **Zoneless gotcha**: components that keep state in plain fields must call `ChangeDetectorRef.markForCheck()` after an `await` (or use signals); otherwise the view never updates (the sales dashboard stayed on its spinner). All data access goes through `SupabaseDbService` with table names from `shared/models/constans/db/tableName.enum.ts`; server-side operations (order creation, transactional emails) go through `EdgeFunctionsService`.
- **Dynamic content (GrapesJS CMS)**: pages are built in the admin editor (`/admin/dynamic-content/editor/:id`) and stored in the `dynamic_components` table (`html_content`, `css_content`, `js_content`, `project_data`). They are rendered with `[innerHTML]` by `features/home/home.ts` (slug `home`) and `features/home/dynamic-page/` (`/content/:slug`). The stored CSS is wrapped in `@scope ([data-home-content])` / `@scope ([data-dynamic-page-content])`, the stored JS is injected after a 2s delay, and elements with `data-access="logged-in" | "anonymous"` are stripped per auth state. Edit content through the editor (or its GrapesJS API) so `project_data` stays in sync with `html_content`. `app.ts` registers Angular Elements (`el-product-card`, `el-dynamic-carousel`) that can be used inside that HTML. Page HTML carries a `data-cheyn-page="<slug>"` attribute that `styles.css` targets.
- **Two Tailwind engines**: build-time Tailwind v4 (`@import 'tailwindcss'` in `src/styles.css`, wrapped in `@layer`) for Angular templates, plus the runtime `@tailwindcss/browser` CDN script in `src/index.html` so classes inside dynamic content work. The runtime script scans the whole document and emits unlayered rules, which beat the layered build-time utilities. Variant/arbitrary utilities on static components (`dark:*`, `sm:/lg:` visibility or grid, `h-[..]`, `translate-*`, `scale-*`, `hidden`) can silently stop applying. Established fixes: literal CSS in the component's `styles` or `[style.*]` bindings for static components; scoped `!important` overrides in `src/styles.css` (keyed on `[data-cheyn-page]` or the compiled class name) for dynamic content. Do not add `<style type="text/tailwindcss">` to `index.html` — Angular's Vite pipeline tries to compile it and the dev server returns 500.
- **Dark mode**: `DarkModeState` toggles `.dark` and `.p-dark` on `<html>` and persists to `localStorage['zg-dark']`; PrimeNG uses `darkModeSelector: '.dark'`. PrimeNG tables/dialogs switch to their own dark theme, so text inside them needs explicit `dark:` colors.
- **Layout**: the navbar is `position: fixed` and its height varies (advertising banner, extra profile row under 400px). `MainLayout` measures the `<header>` with a `ResizeObserver` and applies it as `padding-top`; don't reintroduce fixed padding values.
- `features/lab` is a temporary visual playground route; `shared/components/ecosystem-diagram` is currently unused (the live ecosystem diagram is GrapesJS content).

## Conventions (from `docs/rules.md`)

- Tailwind for styling; no component CSS files (generate with `--inline-style`).
- New control flow only (`@if`, `@for` with `track`, `@defer`); signals over RxJS except for async streams.
- Import environment config from `src/environments/environment` (the dev file is swapped in via `fileReplacements`).
- Features should not import from other features; `shared/` holds reusable UI.

## Deployment / git

- `origin` is `ConcienciasPlayground/zona-green`. Pushes to `main` are force-mirrored by `.github/workflows/mirror.yml` to `ConciencIAs/mirror-zona-green` (the deployed site), so changes reach `main` through pull requests.
- Supabase Auth's Site URL points to the production mirror, so magic links redirect there even from localhost; password login works locally.
